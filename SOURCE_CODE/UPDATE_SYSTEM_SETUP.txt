ServoERP - Desktop Update Release Source of Truth
=================================================

THIS FILE NOW DOCUMENTS THE ONLY SUPPORTED DESKTOP UPDATE FLOW.

ServoERP desktop auto-updates are released through:

- Velopack
- GitHub Releases
- `.github\workflows\desktop-release.yml`

Do not ship desktop updates by manually changing `marketing_site\version.txt`, manually editing update URLs in `UpdateService.cs`, or manually uploading an installer as the primary release action. Those older website steps are not the updater source of truth.

SUPPORTED RELEASE FLOW

1. Intentionally set the source version with:
   `.\scripts\Set-ServoVersion.ps1 -Version <MAJOR.MINOR.PATCH>`
2. Push to `main` or run the GitHub Actions workflow manually.
3. Let CI stamp the final release version using `VERSION + GITHUB_RUN_NUMBER`.
4. CI must reject the run if the candidate version is not greater than the latest published GitHub Release.
5. CI builds the Release app, prepares the publish folder, and packs Velopack artifacts.
6. CI must reject the run if the Velopack output is incomplete or does not contain the expected version in `RELEASES`.
7. CI publishes the GitHub Release only after the guards pass.

RELEASE AUTHORITIES

- Desktop update feed: GitHub Releases
- App update client: `SOURCE_CODE\SERVICES\UpdateService.cs`
- Startup bootstrap: `SOURCE_CODE\Program.cs`
- CI packaging and publish: `.github\workflows\desktop-release.yml`
- Release operations guide: `Docs\CI_CD_AUTO_UPDATE.md`

WEBSITE FILES

The website may still publish:

- `marketing_site\version.txt`
- `marketing_site\latest.json`
- `marketing_site\changelog.json`
- `marketing_site\download\`

These are informational or marketing assets. They do not define the desktop updater release state.

VERSION NUMBERING GUIDE

1.0.0 -> First release
1.0.1 -> Small bug fix
1.1.0 -> New features added
2.0.0 -> Major redesign or breaking change

PERMANENT RULE

If a future change conflicts with this file, `Docs\CI_CD_AUTO_UPDATE.md`, or the current Velopack/GitHub Actions flow, the desktop update channel must remain Velopack + GitHub Releases unless Harshal explicitly approves a platform migration.
